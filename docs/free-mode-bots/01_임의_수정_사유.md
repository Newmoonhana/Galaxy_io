# 원본과 다르게(임의로) 수정한 부분과 그 이유

브랜치: `pr/free-mode-bots` (기준: `origin/remake_ingame` 2e7ad177)
배포용 브랜치: `feature/free-mode-bots` (기준: 465b8e20, 로컬 서버 운영용. PR 대상 아님)

이 문서는 원작자 구현을 그대로 따르지 않은 곳, 요청을 해석해서 정한 곳, 반영하지 못한 곳을 모아 둔 것입니다.

## 1. 개발 환경 때문에 바꾼 것 (PR 에는 들어 있지 않음)

| 무엇 | 왜 | PR 에서는 |
|---|---|---|
| 비공개 엔진 패키지 `com.newmoonhana.nmhnengine` 대신 컴파일된 `Newmoonhana.Runtime.dll` 을 담은 대체 패키지를 프로젝트 안에 넣음 | 비공개 GitHub 저장소라 받을 수 없었음. 배포된 서버 빌드의 DLL 을 꺼내 씀 | **제외.** manifest 는 원래 git 주소 그대로 |
| 프리팹, 씬 13곳의 스크립트 참조(GUID)를 DLL 클래스로 바꿈 | 패키지 스크립트 GUID 가 없어 Missing Script 가 됐음 | **제외.** 프리팹, 씬은 하나도 바꾸지 않음 |
| `WebSingletonPreload` (웹에서 설정 에셋을 미리 비동기로 읽음) | 대체 DLL 이 Windows 서버용으로 컴파일돼 웹 전용 분기가 없음. 웹에서 동기 어드레서블 로드로 멈췄음 | **제외.** 진짜 패키지에는 필요 없음 |
| `PF_Core` 의 바탕 프리팹(패키지의 Core)이 없어 사운드(MasterAudio, SoundManager)가 없음 | 위와 같은 이유 | 해당 없음. 진짜 패키지로 빌드하면 소리가 남 |

배포용 브랜치는 이미 빌드해 둔 PC 클라이언트, 기존 웹 클라이언트와 접속 호환을 지키려고 465b8e20 기준으로 남겨 둠(아래 3절).

## 2. 공용 파일을 고친 곳과 이유

새 기능은 가능하면 새 파일(`DOTS/Bots`, `DOTS/Spectator`, `Managed/Mobile`, `Managed/Spectator`)에 두었고, 공용 파일은 꼭 필요한 줄만 고쳤습니다. **RPC, 고스트(복제) 구조는 하나도 바꾸지 않았습니다.**

| 파일 | 바꾼 것 | 이유 |
|---|---|---|
| `DedicatedServerConfig.cs` | `Bots`, `Enemies`, `Spectator` 설정 항목 추가 | 서버 봇, 몹 생성량, 관찰자 접속을 server_config.json 으로 조절 |
| `ProjectileDamageSystem.cs` | 피해에 배율 표(`BotDamage.For`) 곱함. 봇이 쏜 것은 킬 로그 이름에 봇 무리 이름 | 봇/플레이어/AI 적 피해 조정, 킬 로그에 어느 세력 봇인지 표시. 봇이 없는 서버는 배율 1 |
| `SpaceshipCollisionSystem.cs` | 박치기 피해 배율(`BotDamage.RamFor`), 봇 무리 이름 | 돌격 베히모스(박치기 무리) 박치기 강화, 킬 로그 |
| `SpaceshipDeathSystem.cs` | 봇 격추는 킬 로그에서 뺌, 봇 무리 전멸 시 "누가 -> [봇]무리 전멸" 한 줄 | 봇끼리 킬 로그가 넘치지 않게. 봇도 PlayerNameComponent 가 있어 플레이어로 잡혔었음 |
| `PlayerSpawnSystem.cs` | 관찰자 이름의 스폰 요청은 건너뜀(이름 검사보다 앞) | 관찰자는 우주선 없이 접속 |
| `EnemySpawnSystem.cs`, `EnemyDespawnSystem.cs` | 봇, 관찰자를 플레이어 계산에서 뺌. 상한을 플레이어 수에 비례 | 봇 주변에 몹이 쌓이거나 관찰자의 큰 복제 반경 때문에 몹이 잘못 생기던 문제 |
| `NetcodeDriverConstructor.cs` + 새 `WebSecureConnection.cs` | https 페이지면 `wss://호스트:7980` 으로 접속 | https 페이지는 ws:// 를 막음. 이 PC 의 Caddy(TLS 프록시)가 7980 -> 7979 로 넘김 |
| `LobbyBootstrap.cs` | 관찰자 접속, https 면 wss 포트, 페이지 닉네임 | 아래 4절 |
| `PlayerInputEncodeSystem.cs` | 터치 조작 중이면 가상 조이스틱 값을 씀 | 모바일 웹 플레이 |
| `FollowPlayerEntity.cs` | 터치 조작 중 시야 버튼, 세로 화면 시야 넓힘, 터치가 흉내 낸 마우스로 카메라를 밀지 않음 | 모바일 웹. PC 는 그대로 |
| `PingView.cs`, `CarrierOrderView.cs` | 터치: 핑/명령 버튼 뒤 탭한 자리 | 마우스 버튼이 없는 모바일에서 핑, 함재기 명령 |
| `ChatView.cs` | 닉네임 링크(파티 초대, 수락)를 `Pointer.current` 로 | 터치로도 누를 수 있게. 마우스 동작은 같음 |
| `RadarView.cs` | 관찰자일 때 레이더 중심, 범위를 관찰 지점 기준 | 관찰자 클라이언트 |
| `WebGLTemplates/GalaxyIO/index.html` | 닉네임 입력 화면, 터치 버튼 줄, 브라우저 제스처 차단, 전체화면 | 웹 닉네임, 모바일 |

## 3. 접속 호환에 대해

- 원작자의 11-05 커밋(1차, 2차 개선)이 `SpawnRequestRPC.Hold` 와 `PlayerNameRejectedRPC` 를 추가해 접속 규칙이 바뀌었습니다.
- PR 브랜치는 이 변경을 **그대로 둡니다**(원작자 기능을 되돌리지 않음). 그래서 PR 브랜치로 만든 서버에는 그 이전에 빌드한 클라이언트가 접속할 수 없고, PC, 웹, 관찰자 클라이언트를 같은 커밋으로 다시 빌드해야 합니다.
- 지금 이 PC 에서 돌고 있는 서버는 배포용 브랜치(465b8e20 기준)로 빌드해, 이미 배포한 클라이언트와 호환됩니다.

## 4. 요청을 해석해서 정한 것 / 원작자 구현과 합친 방식

| 항목 | 정한 방식 | 다르게 원하면 |
|---|---|---|
| 웹 닉네임 | 원작자 방식(웹은 hold 로 입장, 리스폰 창에서 이름 입력)을 유지하고, 페이지(index.html)에서 입력한 닉네임을 리스폰 창 입력란에 **미리 채움**. 이름 검사, 거절 경고는 원작자 코드 그대로 | 페이지 입력 없이 리스폰 창만 쓰려면 index.html 의 시작 화면을 빼면 됨 |
| 혼자 다니는 기체(노업, 중업, 풀업) | 3척 편성에 나온 6기종(헬버드, 벌처, 뱅가드, 벡스, 센티넬, 나이트호크) x 3 = 18 세력 | 전 기종으로 늘리려면 `BotDefaults.Solos()` 의 목록에 추가 |
| "플레이어 가시 거리" | 클라이언트 화면 시야(초계함 최대 시야 크기 x 16:9 가로 비율) x 0.85 를 봇의 플레이어 발견 거리 상한으로. 레이더 거리가 아님. 저격, 박치기 무리는 제외 | `PlayerSightScale` |
| 몹 약화, 생성량 감소 | `Enemies` 기본값(상한 15 + 24/명, 체력 x0.8, 피해 x0.8). **설정 파일에 Enemies 항목이 없는 모든 데디케이티드 서버에 적용됨** | server_config.json 의 `Enemies` 로 조절(HealthScale 1, DamageScale 1, CapPerPlayer 30 이면 이전과 비슷) |
| 플레이어 강화 | 자유 모드 봇 서버에서만: 투사체 피해 x1.1, 최대 체력 x1.1, 강화 한 단계 상승폭 x1.25(피해, 체력, 수리). 이동 능력치는 클라이언트 예측과 어긋나므로 건드리지 않음 | `PlayerDamageScale`, `PlayerHealthScale`, `PlayerUpgradeGain` |
| 모바일 조작 | 참고 웹 게임(space-2d-game.vercel.app) 방식: 떠다니는 조이스틱, 끝까지 밀면 가속, 조준하면 사격. 핑, 함재기 명령, 파티는 참고 게임에 없어 버튼 + 탭, 채팅 닉네임 터치로 새로 만듦 | |
| 화면 배치(모바일) | 원작자 UI 프리팹은 건드리지 않고, 터치 중에만 실행 시점에 레이더, 킬 로그, 채팅 위치를 옮기고 조작법 창을 숨김(MobileCanvasFitter). 원작자 아트(프리팹, 스프라이트, 셰이더)는 그대로 | 프리팹에 모바일 배치를 직접 만들면 더 깔끔함 |

## 4-2. 참고 웹 게임 시스템을 원작 스타일로 넣은 것

클론의 동작 방식만 참고하고, 이미지, 코드는 가져오지 않음. 그림은 직접 만든 셰이더와 코드로 만든 픽셀 텍스처, 원작 폭발 프리팹, 원작 사운드 그룹을 씀.

| 시스템 | 파일 | 원작과 다르게 정한 것 |
|---|---|---|
| 늦게 따라오는 카메라, 시야 비례 앞 보기 | `FollowPlayerEntity.cs` | `lookAheadDistance`(고정 5) 대신 `lookAheadRatio`(시야 크기 x 0.32), `followSpeed` 6. 휠 확대 범위는 원작 그대로(축소는 최대 시야까지만: 봇 발견 거리가 화면 시야 기준이라 넓히지 않음) |
| 엔진 불빛, 가속 불꽃, 잔상 불똥, 충전 빛 | `Managed/Effects/SpaceshipVfxView.cs`, `SO_SpaceshipEngineLayout`(+ `GalaxyIO/VFX/엔진 위치 측정` 도구) | 노즐 위치는 원작 스프라이트에서 측정. 추진 상태는 복제되는 속도로 판정(입력은 다른 클라이언트에 없음). 플레이어 기종만(함재기, AI 적 제외) |
| 크기별 파괴 효과 | `Managed/Effects/DestructionFxView.cs`, `SpaceshipDestructionReceiveSystem.cs`(크기를 찾아 클라이언트 메시지로 넘김) | 히트 스톱(화면 멈춤)은 넣지 않음: 네트워크 게임이라 로컬 시간을 멈추면 예측이 어긋남. 대신 흔들림 |
| 속도 먼지 | `Managed/Effects/SpeedDustView.cs` | 배경 별 시차는 원작이 이미 3겹이라 그대로 둠 |
| HP 숫자, 수리 남은 시간, 주포 재장전, 자동 포탑 상태, 과열 임박 | `Managed/UI/CombatFeedbackView.cs`, HUD 씬 `CombatFeedback` | 열 게이지는 원작이 이미 색 변화, 흐르는 빛, 과열 연출을 가지고 있어 그대로 둠. 수리 대기와 자동 포탑 휴식은 복제되지 않는 값이라 클라이언트 추정 |
| 새 에셋 | `Shaders/FX-Additive.shader`, `Arts/Sprites/VFX/M_FxAdditive.mat`, `Arts/Sprites/UI/Hud/T2D_HudRing_01.png`, `T2D_HudPip_01.png` | 원작 명명 규칙 |
| 사운드 | 원작 PF_Core 그룹: 재장전 완료, 충전 완료 `UI_Press`, 큰 배 폭발 `ThorExplosion` | 엔진 소리, 재장전 전용 소리는 그룹이 없어 넣지 않음(새 그룹은 진짜 패키지 에디터에서 PF_Core 에 추가 필요) |

## 5. 반영하지 못한 것 (최종 보고에도 포함)

- **웹 배경음악/효과음**: 배포용 브랜치는 비공개 패키지가 없어 소리가 없습니다. 대체 Core 프리팹을 만드는 중입니다. PR 브랜치(진짜 패키지)는 해당 없음.
- **PR 브랜치 컴파일 검증**: 이 PC 에는 진짜 엔진 패키지 0.0.37 이 없어 PR 브랜치를 그대로 열어 컴파일할 수 없습니다. 우리 코드는 엔진 패키지 API 를 새로 쓰지 않도록 했고(기존 파일에 원래 있던 using 만), 프로젝트 쪽 타입만 씁니다. 패키지가 있는 환경에서 한 번 열어 컴파일 확인이 필요합니다(02 문서).
- **4-2 의 시스템 화면 확인**: 빌드, 실행 테스트 없이 컴파일만 확인함(사용자 지시). 크기, 밝기, 위치 값은 실제 화면에서 조정이 필요할 수 있음. 모두 인스펙터 값(SerializeField)으로 조절 가능.
- **관찰자 패널 원작 스타일**: 관찰자 기능(플레이어, 함대, 함선 고정, 자유 시점, 확대, 레이더, 모든 함대 표시)은 동작하지만 패널은 Unity IMGUI 그대로. 원작 UI(PopupBase, 네온 창, Galmuri)로 바꾸는 일은 남음.
- **모바일 기기별 화면 확인(플립, 폴드, 태블릿)**: 하지 않음(사용자 지시).
- **다른 모드(대장선 잡기, 점령전) 서버 실행 테스트**: 하지 않음(사용자 지시). 봇과 피해 배율은 자유 모드에서만 켜지게 되어 있음. 몹 체력 x0.8 은 모든 모드에 적용됨.
- **배포용 브랜치에 원작자 11-05 UI 개선 반영**: 접속 호환을 지키기 위해 배포용 서버, 클라이언트에는 아직 넣지 않았습니다.
